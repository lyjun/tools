# Coding Standards

> Write code that humans can understand. — Martin Fowler

## Universal Principles

跨語言、跨情境的通用準則。撰寫、review、重構程式碼時皆適用。

### Core Values

Readability First · KISS · DRY (Rule of Three) · YAGNI · Explicit over Implicit

### Conflict resolution

When principles conflict: **YAGNI > KISS > SOLID > DRY**

- *Duplication is far cheaper than the wrong abstraction.* — Sandi Metz
- Extract an interface only when a second implementation actually exists, or a mock has actually been written. "Future flexibility" is not justification.

### SOLID (enforced thresholds)

- **SRP**: One function/module does one thing. Target 20-50 lines, split at 50+
- **ISP**: Interfaces should be small and focused
- **DIP**: Depend on abstractions, inject dependencies at construction time (language-specific rules may override injection style)

### Practices

- **Naming**: Self-documenting (`userSearchQuery` > `q`), extract magic numbers to constants
- **Errors**: Fail fast, meaningful messages, distinguish expected vs program errors
- **Comments**: Explain WHY not WHAT. If comment needed → refactor first
- **Structure**: Early return (max 3 nesting levels), composition over inheritance (max 2-3 levels)
- **Build config**: Don't modify Makefile/Dockerfile/CI unless that's the task itself
- **Generated files**: Before hand-editing any file that looks generated (has a generation header, matches exclusion patterns, or lives alongside a generator script/Makefile target), check for the generation tooling and use it

### Dependencies (mandatory)

1. **Project internal** — search existing modules first
2. **Standard library** — stable, well-maintained
3. **Third-party** — evaluate necessity, search project for duplicates before adding

### Code Smells (thresholds)

- Function > 50 lines → split
- Nesting > 3 levels → early return / extract
- Magic numbers → named constants
- 3+ duplications → extract common function
- Parameters > 3-4 → wrap in struct/object
- God class/function → split by concern

### Script Language Choice

Shell script（bash/zsh）適合簡單膠水（< 50 行、純 CLI 串接）。符合以下任一條件時改用 Python：
- 超過 50 行
- 涉及跨平台差異的文字處理（不同 OS 的 CLI 工具行為可能不同）
- 需要結構化資料處理（JSON parse、dict/list 操作）

### Generated & Lock File Exclusions

下列 pattern 應排除於 code review / improvement 掃描範圍。其他 skill 引用本列表，更新請改這裡，不要散落到個別 skill。**這一節就是唯一來源** —— consumer 要載的是本檔這一節，不是任何 `references/` 下的檔案，也不是任何語言 gated 的 reference（那樣一份 TypeScript-only 的 diff 會載到零個 reference，filter 直接消失）。

**兩道測試，先跑內容那道。** 檔名 pattern 只是便宜的預篩，攔不完任何 generator 的輸出。

**測試 1（主要）：Go 檔第 1–3 行帶 `Code generated by … DO NOT EDIT.` 就是產物**，不管檔名。這是 `go generate` 的約定，golangci-lint 也用它。實測 workspace：4,720 個 Go 檔裡 656 個帶這個標記，分得乾淨。

這道測試不能用檔名代替，而且**絕不可以**為 sqlc 的其他輸出加檔名 arm。sqlc 每個 package 產五種檔案 —— `queries.sql.go`、`db.go`、`models.go`、`querier.go`，有 batch/copyfrom 時再加兩個 —— 而 workspace 裡 56 個叫這些名字的檔案有 6 個是手寫的（`arx-platform-core/internal/database/models.go`、`oauth2-server/internal/auth/db.go`、四份 `api/http/v1/models.go` 與 `internal/handler/v1/models.go`）。加 `models\.go$` 這種 arm 會靜默把那 6 個手寫檔排除在 review 之外 —— 那是比多讀幾個產物嚴重得多的失敗方向。

**測試 2（預篩）：下面這條 ERE。** 它含 `(^|/)` 與 `(yaml|json)`，**是 extended regex** —— 用 `grep -E` 或在 context 內比對，用 BRE (`grep` 不帶 `-E`) 跑會讓 `|` 與 `()` 變字面字元、命中零個檔案然後靜默變成空 filter：

```
\.pb\.go$|_grpc\.pb\.go$|_string\.go$|_gen\.go$|\.gen\.go$|\.sql\.go$|go\.sum$|atlas\.sum$|package-lock\.json$|yarn\.lock$|pnpm-lock\.yaml$|(^|/)swagger\.(yaml|json)$|docs/swagger/|docs/openapi/|docs/proto/|docs/grpc/API-Reference\.
```

非 Go 的產物（lock 檔、swagger、`atlas.sum`）沒有內容標記可查，測試 2 是它們唯一的判準。Go 檔兩道都跑，任一命中就排除。

`docs/grpc/` is matched only at `API-Reference.{md,json}` (buf output), **not** dir-wide — that directory also holds hand-written docs (e.g. `TLS-Architecture.md`). `docs/proto/` and `docs/swagger/` are whole-directory generator output (`protoc-gen-doc --doc_out`, `swag init --output`). `docs/openapi/` is included by convention (openapi-gen output) to match `arx-pr-pre-flight`.

**Three arms exist because a real review paid for their absence.** On an 81-file PR none of the path-anchored arms fired and 6,534 lines of generator output went through a full read:

| arm | catches | why the old list missed it |
|---|---|---|
| `\.sql\.go$` | **one of sqlc's five output files** (`queries.sql.go`) — the other four are caught by test 1, not by any filename arm | sqlc emits `<name>.sql.go`, not `*_gen.go` — `go.md` used to name sqlc under `*_gen.go`, which sqlc has never produced |
| `atlas\.sum$` | Atlas migration lock | `go.sum$` does not match `atlas.sum` |
| `(^|/)swagger\.(yaml\|json)$` | `swag init` output wherever it lands (`api/<svc>/swagger.yaml`) | `docs/swagger/` is path-anchored, and `swag --output` is routinely pointed elsewhere |

The swagger arm deliberately excludes `.yml`, and there is no bare `openapi.*` arm: `.github/workflows/` conventionally uses `.yml`, so both would swallow hand-written CI workflows (verified — a bare openapi arm matched `.github/workflows/openapi.yml`). Keep any new arm's filename form narrow enough that a workflow file cannot match it.

`*.sql.go` is sqlc's *default* output name rather than a reserved one, and this list governs every repo in the workspace, so it was swept before being added: all 16 tracked `*.sql.go` files across the workspace are named `queries.sql.go` and every one carries the `Code generated by sqlc. DO NOT EDIT.` header — no hand-written file matches. Should one ever appear, narrow this arm to `queries\.sql\.go$` rather than dropping it.

**Sweep for both directions before adding an arm, and sweep the workspace rather than the repo in front of you.** That first sweep only asked "does this arm catch a hand-written file?" (over-match) and answered no. Nobody asked "what else does this generator emit?" (under-match) — and the answer was 50 more files, 2,178 lines, which is why test 1 above now carries the weight. `zz_generated.deepcopy.go` (deepcopy-gen, 3 files / 1,612 lines) and kubebuilder's `PROJECT` were escaping for the same reason.

### HTTP API Response Design

- **No omitempty on response fields**: GET response 的所有欄位都要顯示，空值用零值（`""`、`0`、`false`、`[]`）而非省略。前端直接綁定欄位，不需判斷 key 是否存在
- **Empty array = `[]`, not `null`**: slice 欄位初始化為空 slice，確保 JSON 序列化為 `[]`

### Testing & Performance

Test meaningful behavior, not for coverage. Correctness → measure → optimize.
